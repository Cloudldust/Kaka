基于 Rust + egui + rusqlite 技术栈，为保证 <1.5秒的启动速度和 <80ms 的切换延迟，需采用严格的分层架构与异步任务调度。

## 一、 整体架构分层

自上而下分为四层，层与层之间通过接口和事件解耦：

1. **UI 表现层**：基于 `eframe/egui`，纯视图层，不包含业务逻辑，只负责消费状态并渲染。
2. **应用逻辑层**：核心业务大脑，处理导入流、状态机、快捷键分发、撤销重做栈。
3. **数据持久层**：基于 `rusqlite`，负责数据库读写、缓存索引管理、断点续传 JSON 处理。
4. **系统 IO 层**：负责文件遍历、EXIF 解析、RAW 异步解码、磁盘空间检测、Windows 回收站调用。

## 二、 核心模块拆解与开发任务流

### 模块 1：基建与冷启动（基石）
* **任务 1.1：数据库初始化模块**。建立 `meta`, `photos`, `folders`, `workspace_state` 四张表，执行索引建立，开启 WAL 模式。
* **任务 1.2：数据库维护模块**。实现 Schema 迁移机制（10.5）与 `PRAGMA integrity_check` 损坏修复流程（10.6）。
* **任务 1.3：状态恢复模块**。启动时依次检测：数据库损坏 -> 续传临时文件 -> `last_crash_marker` 崩溃标记。按优先级弹窗并恢复 `workspace_state`。
* **任务 1.4：主窗口骨架**。搭建 egui 基本布局（顶部栏、进度条、大图预览区、右侧面板、底部缩略图条、状态栏、设置入口），实现 1024x640 硬约束与 DPI 感知。

### 模块 2：导入引擎（重 I/O）
* **任务 2.1：文件扫描与过滤模块**。遍历磁盘，按支持格式白名单过滤，支持递归开关。
* **任务 2.2：EXIF 解析模块**。提取拍摄时间、相机/镜头型号等三要素。重点实现多编码兼容策略（ASCII -> UTF-8 -> GBK -> Shift-JIS -> EUC-KR -> Hex 兜底）。
* **任务 2.3：RAW+JPG 配对模块**。同目录同名 + 时间差 ≤5秒 判定为一组，分配 `pair_group_id`。
* **任务 2.4：去重与路径修复模块**。三要素查库比对，命中且路径失效则更新 `current_path`（记录 R 条）。
* **任务 2.5：拷贝与续传控制模块**。实现磁盘空间预检测（5%+512MB 缓冲）。执行物理拷贝，逐条写入临时 JSON，写入数据库。处理平铺模式 `_dup` 重名追加。

### 模块 3：缓存与解码系统（重性能）
* **任务 3.1：后台异步任务池**。基于 Rust 线程池，处理缩略图生成、预览图生成、RAW 视口解码。
* **任务 3.2：磁盘缓存管理器**。按 `{thumb_hash}.jpg` 规则读写缓存，管理 `cache_index.db`。实现 LRU 淘汰与 20GB 容量上限清理。
* **任务 3.3：RAW 视口解码器**。Z 键放大时，先 0 延迟显示内嵌 JPG，后台线程仅解码当前可见矩形区域的 RAW 像素，解码完成后无缝替换。
* **任务 3.4：内存缓存管理器**。LRU 策略，2GB 上限。预读当前照片前后各 1 张的屏幕适配大预览图。

### 模块 4：核心筛选工作区（重交互）
* **任务 4.1：状态机与数据过滤**。按 `folder_path` 前缀匹配加载工作区。实现基于 EXIF、状态、相机型号等条件的 SQL 动态拼接过滤（7.8）。
* **任务 4.2：快捷键路由与撤销栈**。全局拦截键盘事件，区分单步操作（入栈，最大 100 步）与批量操作（不入栈）。处理冲突检测。
* **任务 4.3：多选与批量操作**。维护 `HashMap<PhotoId, Selection>` 状态，处理 Ctrl/Shift 范围选择，执行批量 Q/E/U 状态变更。
* **任务 4.4：直方图渲染**。基于 RAW 或 JPG 像素数据统计 R/G/B/L 通道分布，使用 `egui::Shape::mesh` 绘制，并判定 3% 溢出警告。

### 模块 5：待删与导出闭环
* **任务 5.1：待删框与安全删除**。模态框加载 `status=1` 的照片。调用 `windows-rs` 的 `SHFileOperationW` 将文件移入回收站，事务清空数据库记录。
* **任务 5.2：导出与 LR 联动**。实现保留照片的物理拷贝、XMP 侧车生成（写入 `xmp:Label` 和 `tiff:Orientation`）。读取注册表检测 LR，生成 `.lrtemplate` 并唤起进程。

## 三、 开发阶段建议路线图

为了快速可用，建议分四个里程碑迭代：

* **M1 (MVP 核心流)**：完成基建 + 添加模式导入 + 纯 JPG 缩略图显示 + Q/E 筛选 + 崩溃恢复。此阶段可验证 egui 响应速度和数据库设计。
* **M2 (导入补全与 RAW 支持)**：完成复制模式 + 断点续传 + RAW 格式 EXIF 提取 + 异步缩略图缓存系统。
* **M3 (极速筛选体验)**：完成 Z 键视口解码 + 直方图 + 高级过滤 + 多选与批量操作 + 撤销栈。
* **M4 (闭环与交付)**：完成待删回收站删除 + 导出 XMP/列表 + LR 联动 + 设置面板完善 + DPI 适配与打包签名。
