# 咔咔（Kaka）产品需求文档（PRD）



一、产品定位

相机照片导入与快速筛选工具。只做导入和筛选两件事，不做后期修图。定位轻量、快速、键盘驱动。


二、支持格式

2.1 支持的图像格式（含扩展名，大小写不敏感）

RAW格式（厂商专有）：
- NEF（尼康）：.nef .nrw
- CR2/CR3（佳能）：.cr2 .cr3
- ARW/SR2/SD1（索尼）：.arw .srf .sr2
- RAF（富士）：.raf
- PEF/PTX（宾得）：.pef .ptx
- ORF（奥林巴斯/OM System）：.orf
- RW2（松下）：.rw2
- DNG（Adobe通用）：.dng
- RAW（通用兜底）：.raw .raws .iiq（飞思）.3fr（哈苏）.x3f（适马）

非RAW格式：
- JPEG：.jpg .jpeg .jfif
- PNG：.png
- TIFF：.tif .tiff（仅8bit/16bit非压缩/LZW/ZIP压缩，不支持JPEG压缩的TIFF）
- HEIC/HEIF：.heic .heif（仅8bit，依赖系统编解码器，解码失败则跳过并在日志记录）

2.2 不支持格式（自动过滤，不进入待导入列表）

- 视频文件：.mp4 .mov .avi .mkv .mts .m2ts .wmv .flv
- 音频文件：.mp3 .wav .flac .aac
- 文档文件：.doc .docx .pdf .xls .xlsx .ppt .pptx
- Sidecar文件：.xmp .dop（Lightroom侧车）.pp3（RawTherapee侧车）
- 系统隐藏文件：Thumbs.db、.DS_Store、桌面.ini等

2.3 格式兼容兜底策略

- 识别为RAW但本软件无法解码的格式：读取其内嵌预览JPG（若存在）用于缩略图与预览区显示，标记该照片为"仅预览模式"，Z键放大时提示"此RAW格式暂不支持完整解码，仅显示内嵌预览"。
- 内嵌预览JPG也不存在的格式：跳过该文件，导入日志记录"格式不支持且无内嵌预览：{filename}"。
- HEIC解码失败：依赖Windows 10/11 HEIF图像扩展，若用户未安装则HEIC文件全部进入失败列表，提示栏显示"检测到N张HEIC照片无法解码，请在微软商店安装「HEIF 图像扩展」后重试"。


三、技术栈

Rust + egui。纯静态编译，单EXE分发，无需额外DLL。

数据库：SQLite。使用 rusqlite 库，开启 bundled 特性，SQLite 引擎源码静态编译进 EXE。用户无需安装任何数据库软件，双击 EXE 即可运行。

数据库文件：首次启动时自动创建在 %APPDATA%/Kaka/kaka.db。该文件存放所有照片记录和工作区状态。


四、性能目标

参考硬件：AMD 9600X + RTX 5060 + 三星M.2 SSD

启动至筛选界面（含1000张NEF）：< 1.5秒（仅显示文件列表+加载已缓存缩略图，不含首次生成缩略图）
首次生成100张缩略图（后台异步）：< 8秒
照片切换延迟：< 80ms（已缓存缩略图）/ < 300ms（需从RAW实时提取）
Z键放大（100% RAW解码当前视口）：< 500ms
1000张RAW导入+去重+生成缩略图总耗时：< 5分钟
内存峰值：< 2.5GB


五、工作流总览

导入 -> 筛选 -> 后期（后期在LR中完成，本软件不涉及）


六、导入模块

6.1 两种导入模式

复制模式（Copy）：从存储卡导入新拍摄的照片。物理拷贝照片至用户指定的目标目录，保留原始文件名（不添加任何前缀/后缀/变量）。数据库记录拷贝后的绝对路径。

添加模式（Add）：导入电脑硬盘上已存在的照片文件夹。不拷贝文件，仅扫描并建立数据库索引。命名规则完全禁用（文件不动，改名无意义）。数据库记录原始绝对路径。

6.1.1 子文件夹递归扫描

开关名：「递归扫描子文件夹」，复制/添加模式均可用，默认开启。
- 开启：从源路径向下遍历所有层级子文件夹，发现支持格式即纳入待导入列表。
- 关闭：仅扫描源路径直接一级目录下的文件，不进入子文件夹。
- 复制模式下保持相对目录结构：若开启递归且源为 D:\DCIM\，源中有 D:\DCIM\100NIKON\DSC_0001.NEF，则目标目录也创建 目标目录\100NIKON\DSC_0001.NEF（见6.1.2）。

6.1.2 复制模式目标目录结构规则

源根路径定义：源根路径 = 用户在导入界面手动选中的源文件夹路径（不是存储卡根目录）。例如用户手动选中 D:\DCIM\100NIKON\ 作为源，则源根路径即为 D:\DCIM\100NIKON\。保持原结构时以此为基准剥离前缀重建相对子目录。

用户在「目标目录」下可选择子目录组织方式（仅复制模式可用，添加模式无此选项）：
选项A - 保持原结构（默认）：相对于源根路径（用户选中的路径），在目标目录下重建相同的相对子目录层级。例：源根 D:\DCIM\100NIKON\，文件 D:\DCIM\100NIKON\DSC_0001.NEF → 目标根 E:\Photos\2026-08-24\ → 最终 E:\Photos\2026-08-24\DSC_0001.NEF（不再额外嵌套 100NIKON 子目录，因为源根本身就是用户选中的 100NIKON）。若源路径直接一级文件（无子文件夹），则文件直接落入目标根。
选项B - 按拍摄日期建子文件夹：按每张照片的 EXIF 拍摄时间（capture_time，YYYY-MM-DD）自动建子文件夹。例：目标根 E:\Photos\ + 拍摄时间2026-08-23 → E:\Photos\2026-08-23\DSC_0001.NEF。无EXIF拍摄时间的照片（使用mtime兜底的）统一落入「未知日期」子文件夹。
选项C - 全部平铺：所有文件直接落入目标根目录，不建任何子文件夹。若发生文件名冲突（两张不同的照片但文件名同为 DSC_0001.NEF），在文件名后追加 _dup1、_dup2…，如 DSC_0001_dup1.NEF，并在导入日志中记录冲突。若发生文件名冲突追加 _dup 后缀，其同名 Sidecar 文件（.xmp 等）必须同步追加相同后缀，保证关联不断裂（例：DSC_0001.xmp → DSC_0001_dup1.xmp）。

6.1.3 RAW+JPG 配对处理

配对判定规则：同目录下，文件名主体完全相同（去除扩展名）、EXIF拍摄时间差 ≤ 5秒、文件大小差不限 → 判定为「RAW+JPG一组」。例：DSC_0001.NEF + DSC_0001.JPG 为一组。
- 阈值说明：默认 ≤ 5 秒（兼容部分相机双卡槽记录相差 1-2 秒的情况）。若后续发现误配对，可在设置中提供 1-30 秒的阈值调节项（默认 5 秒）。

行为定义（全局生效，不可关闭）：
- 筛选界面：一组配对照片在缩略图条与预览区视为「同一张」，只显示 RAW 的缩略图，右下角角标显示「RAW+JPG」小字。
- 去重：两个文件分别使用各自的三要素独立去重。若 RAW 已存在但 JPG 是新的，或反之，则只导入缺失的一方，并在导入后重新检测配对。
- Q（待删）：对整组标记待删。待删框中显示为一张缩略图，角标「RAW+JPG」。最终删除时，两个文件同时移入回收站，数据库两条记录同时删除。
- 单独移动/丢失：若用户手动删除了配对中的 JPG 但保留了 RAW，则下一次软件启动时自动解除配对关系，该照片降级为纯RAW显示。
- Sidecar 文件跟随：配对中若存在同名 .xmp（如 DSC_0001.xmp），复制模式下一并拷贝，但不纳入数据库，不显示在界面上。

6.1.4 复制模式磁盘空间预检测

在用户点击「导入」按钮后、实际开始拷贝前执行：
1. 统计待拷贝的所有文件（含配对JPG、XMP侧车）总字节数，记为 total_size。
2. 查询目标目录所在磁盘的可用字节数，记为 free_size。
3. 预留缓冲：需要 free_size ≥ total_size × 1.05 + 512MB（5%冗余+512MB最小缓冲），否则阻断导入。
阻断时弹窗提示：「目标磁盘空间不足。需要约 {total_size_human}，可用仅 {free_size_human}。请清理目标磁盘空间或更换目标目录。」提供「更换目标目录」和「取消」两个按钮。
- 中途磁盘写满（极端情况）：已成功拷贝的文件保留在磁盘、写入数据库；未完成的文件进入失败列表，导入报告中按「失败」计数。

6.2 触发方式

自动触发：检测到可移动存储设备插入，自动弹窗进入导入界面（参考LR）。
手动触发：软件界面提供导入入口（具体UI待设计），用户手动选择源路径。

6.3 导入配置选项

复制模式下可配置：
- 目标目录（路径选择框，必须填写，默认空）
- 子目录组织方式（三选一：保持原结构/按日期建目录/平铺，默认保持原结构，见6.1.2）
- 递归扫描子文件夹（开关，默认开启，见6.1.1）
- 去重开关（默认开启）
- 是否清空存储卡（开关，默认关闭；仅当检测到源路径为可移动存储设备时此项可用，否则灰显禁用）

添加模式下可配置：
- 递归扫描子文件夹（开关，默认开启）
- 去重开关（默认开启）
- 目标目录、子目录组织方式、清空存储卡：三项隐藏不可见。

6.4 去重逻辑

去重三要素：原始文件名 + 文件大小 + EXIF拍摄时间。三者完全匹配即判定为已存在。

拍摄时间读取优先级：EXIF中的DateTimeOriginal（拍摄时间）> DateTimeDigitized（数字化时间）> 文件修改时间（mtime）作为兜底。使用兜底时在导入日志中记录"该照片无EXIF拍摄时间，已使用文件修改时间"。

EXIF编码兼容策略（读取拍摄时间、相机型号、镜头型号等字符串字段时）：
1. 先按 EXIF 标准编码 ASCII 尝试解码。
2. 若解码出现乱码或不可打印字符比例 > 30%，尝试 UTF-8。
3. 再失败，尝试 GBK（简体中文相机常见）、Shift-JIS（日文相机）、EUC-KR（韩文相机）按顺序尝试。
4. 全部失败：该字段保留原始字节的 Hex 编码并在导入日志记录警告「字段{fieldname}编码识别失败，已回退Hex显示：{filename}」。
5. 兜底原则：宁可显示乱码提示，也绝不崩溃跳过整张照片。

查询范围：全局数据库，跨所有已导入的文件夹（无论复制还是添加模式）。

命中后的行为：三要素匹配数据库已有记录，界面灰显"已存在"，默认取消勾选。添加模式下不允许强制导入，以保护数据一致性。

路径修复：若数据库中的current_path已失效（文件被用户手动移动或重命名），用户通过添加模式重新导入该文件夹时，三要素匹配后自动更新current_path为新路径，无需额外操作。修复完成后在本次导入报告的单独区域显示"路径修复X张"，并在导入日志逐条列出。

数据库UNIQUE约束冲突兜底：写入数据库时若触发UNIQUE(original_filename, file_size, capture_time)冲突（极端并发或三要素哈希碰撞），执行ON CONFLICT IGNORE静默跳过，不覆盖已有记录，同时在导入日志记录「三要素冲突已跳过：{filename}」。

6.5 导入流程

第一步，选择源路径。复制模式自动检测存储卡盘符或手动选择文件夹。添加模式手动选择本地文件夹。

第二步，配置选项。复制模式配置目标目录和去重开关。添加模式仅配置去重开关。

第三步，去重扫描。遍历源文件，用三要素比对数据库，标记已存在项。

第四步，执行导入。复制模式拷贝新照片至目标目录。添加模式不拷贝，直接进入下一步。

第五步，写入数据库。记录current_path及所有元数据。

第六步，生成缩略图。后台异步生成，不阻塞导入完成。

第七步，导入报告。复制模式显示“成功X张/已存在跳过Y张/失败Z张”及失败文件列表。添加模式显示“已将X张照片添加到图库，文件保留在原位”。

6.6 进度反馈

显示内容：进度条 + 当前正在处理的文件名 + 进度计数。
格式示例：[████████░░░░░░░░░░░░] 正在处理 DSC_0342.NEF（50/380）
不显示预估剩余时间。

6.7 边界情况处理

导入过程用户取消：复制模式已拷贝的文件保留在磁盘，数据库不记录。添加模式已扫描但不写入数据库。临时续传记录同步删除。

损坏或无法读取的文件：跳过该文件，记录错误日志（含文件路径及错误原因），导入完成后展示失败列表。不中断整体流程。

拷贝成功但数据库写入失败：弹窗提示错误，记录失败文件路径，导入完成后展示失败列表。已拷贝的文件保留在磁盘，用户可手动清理或重新导入。

清空存储卡：仅复制模式下可用，提供复选框“导入后清空存储卡”，默认不勾选。清空操作为移到回收站，非永久删除。仅在拷贝+数据库写入均100%成功的文件才会被从存储卡移动到回收站；失败/取消的文件原样保留在卡中。

源文件被用户手动移动或重命名：用户通过添加模式重新导入新路径，三要素匹配后自动更新current_path。

源文件被用户永久删除：数据库记录残留。软件不主动弹窗检测。界面显示“文件丢失”灰标。用户可在筛选界面手动移除记录。

6.7.1 导入中断续传机制（断点续传）

适用场景：复制模式下大批量导入过程中软件崩溃、系统断电、用户强杀进程等非正常中止。

实现方式：
1. 临时状态文件：每次导入任务开始前在 %APPDATA%/Kaka/import_session_{timestamp}_{uuid}.json 创建临时文件，逐条记录「已完成拷贝且已写入数据库」的文件列表。
2. 重启检测：软件启动时扫描 import_session_*.json 目录，若存在未完成的续传记录（即 session 未被正常标记为 completed），弹窗提示：「检测到上次有未完成的导入任务（共{total}张，已完成{done}张）。是否从断点继续？」提供两个按钮：「继续导入」「放弃本次任务」。
3. 继续导入：跳过已完成的文件，从第一张未完成的文件开始继续拷贝+写入数据库+生成缩略图。进度条按总数继续累加。
   - 防呆：断点续传恢复时，无论去重开关是否开启，均强制对未完成文件执行三要素比对（原始文件名+文件大小+EXIF拍摄时间），命中数据库已有记录则跳过拷贝，避免去重关闭状态下重复写入或生成 _dup 冗余文件。
4. 放弃任务：临时文件标记为 abandoned，移动到 %APPDATA%/Kaka/abandoned/ 目录保留7天，便于追溯，7天后自动清理。
5. 正常完成：导入流程正常走完（成功/失败/取消均算），临时文件标记为 completed 并在30天后清理。
6. 添加模式下无续传（因为无拷贝操作，重新导入不产生副作用），不创建临时文件。

6.8 导入完成后反馈

复制模式：弹窗或提示栏显示「成功导入 {X} 张（已存在跳过 {Y} 张，失败 {Z} 张）」，并提供「查看失败列表」按钮。
- 复制模式为全量拷贝生成新文件，不存在「旧路径失效需修复」的场景，因此路径修复 R 固定不显示（恒为 0）。

添加模式：弹窗或提示栏显示「已将 {X} 张照片添加到图库，文件保留在原位（跳过 {Y} 张已存在，失败 {Z} 张，路径修复 {R} 条）」，并提供「查看失败列表」「查看路径修复列表」两个按钮。
- 路径修复说明：R 条记录为数据库中原 current_path 失效，但通过本次添加模式三要素匹配成功后自动更新路径的照片（仅对本次重新添加/重新导入的文件夹生效），属于"只更新路径不重复导入"的场景。R 为独立计数，不归入 X（成功）/Y（跳过）/Z（失败）任何一类。

导入报告完整字段（失败列表 / 路径修复列表）支持导出为 .txt 或 .csv 文件，导出字段：
- 失败列表：序号、源路径、目标路径(复制模式)、失败原因代码、失败原因中文描述、文件大小、三要素捕获时间。
- 路径修复列表：序号、旧路径、新路径、原始文件名、三要素捕获时间、修复时间戳。


七、筛选模块

7.1 核心逻辑

文件原地不动，全靠数据库状态标记。切换文件夹即切换工作区视图，数据库全局共享但按路径过滤显示。

工作区定义：以 folder_path 字段的精确前缀匹配为过滤条件。若当前工作区是父文件夹（同时包含多个子文件夹），则递归显示所有子文件夹中的照片；若用户在文件夹选择器中选择了具体子文件夹，则只显示该子文件夹一级（是否含其子子文件夹由「递归显示子文件夹内容」开关控制，默认开启）。

7.1.1 状态栏计数公式（消除歧义）

总照片数 total = 当前过滤条件下所有照片数量（含未处理/待删/已阅跳过）
已处理数 processed = 待删数 + 已阅跳过数
已筛选进度 = processed / total
保留数 kept = total - 待删数（= 未处理数 + 已阅跳过数）—— 因为未被标记为待删的全部视为保留
待删数 deleted = status = 1 的照片数量
已阅跳过数 reviewed = status = 2 的照片数量
未处理数 untreated = status = 0 的照片数量
说明：「保留数 kept」仅表示「最终删除完成后剩下的照片」，不是"精选"或"打分"。

7.2 默认快捷键

基础筛选：
Q：标记为待删（status=1）。照片右上角显示"待删"角标，待删计数+1，自动跳转下一张。
E：标记为已阅跳过（status=2）。无视觉角标（保持界面干净），已阅跳过计数+1，自动跳转下一张。
U：取消当前照片的所有标记，重置为未处理（status=0）。不自动跳转，停留在当前张。

导航：
左箭头 / A：手动上一张。
右箭头 / D：手动下一张。
Home：跳转到当前工作区第一张。
End：跳转到当前工作区最后一张。
数字键 0-9 + Enter：跳转到第 N 张（例：输入 123 + Enter → 跳到第 123 张）。
跳转边界规则：在第一张按「上一张」或最后一张按「下一张」时停止，不循环。弹出状态栏瞬时提示「已是第一张 / 已是最后一张」（2秒自动消失）。

Z 键与缩放：
Z：切换 100% 像素级放大 / 适配窗口。100% 模式下按 ESC 或再按 Z 返回适配。
100% 模式下：按住空格拖拽画面平移；松开空格恢复。
Ctrl+0：重置为适配窗口（等同于 ESC/Z 复位）。

撤销重做：
Ctrl+Z：撤销上一步 Q/E/U 标记操作（仅状态改变，不影响导航位置），可连续撤销，最大栈深 100 步。
Ctrl+Y / Ctrl+Shift+Z：重做撤销，与撤销栈对应。
工作区切换/关闭软件会清空撤销栈（不持久化）。
- 例外：批量操作（Ctrl+Q/E/U 对多张照片生效，见 7.9.2）不进入撤销栈。批量操作执行前强制二次确认，不可撤销，避免栈溢出。

旋转（仅数据库标记，不修改原文件与EXIF）：
R：顺时针旋转当前照片显示方向 90°。
Ctrl+R：逆时针旋转当前照片显示方向 90°。
Shift+R：重置旋转角度为原始 EXIF 方向。
旋转角度记录在数据库中，不写回原文件、不写回EXIF。导出/送LR时一并写入XMP侧车（若开启）。

杂项：
I：切换右侧信息面板显示/隐藏。
Esc：若当前存在多选状态（选中数 > 0，见7.9），按 Esc 优先清空选区；无多选时，若在Z放大模式则退出放大；若当前有弹出菜单/模态框则关闭；否则无操作。
Space：同右箭头/D，下一张。（摄影师常见肌肉记忆）
Ctrl+S：立即触发一次自动保存（无需等待10秒定时），状态栏瞬时提示"工作区已保存"。
Ctrl+A：全选当前过滤视图中的所有照片（用于批量操作，见7.9）。
Ctrl+Shift+A：取消全选。
Ctrl+I / Ctrl+O：打开导入对话框（键盘驱动入口，见6.2）。

7.2.1 自定义键位范围

允许重映射的键：Q、E、U、Z、R、I、Space、A/D、左右箭头、Ctrl+Z、Ctrl+Y、Ctrl+S、Ctrl+A。
不允许重映射的系统键：ESC、Home/End、数字键跳片、Ctrl+R/Shift+R、Ctrl+0、拖拽平移。
自定义键冲突时的处理：若用户新设置的键与现有某功能键重复，输入框立即显示「与{现有功能名}冲突」红底提示，不允许保存；直到用户修改或先清除被冲突功能的绑定。

7.3 筛选终局

二态模式。只有删除和跳过两种操作。全部看完后，未按过Q且未按过E的算未处理，按过E的算已阅保留。最终只删除按了Q的照片，剩下的全部视为保留。不设精选键。

终局检测：当 processed == total（已处理数 = 总数）时，状态栏「已筛选」变为绿色（#4cdb8a），并在右上角瞬时提示「筛选完成！共 {total} 张，保留 {kept} 张，待删 {deleted} 张」（持续5秒，可关闭）。此时用户仍可按 Q/E/U 重新标记状态（不再自动跳张，除非用户手动触发）。

7.4 100%放大检查对焦（Z键）

按下Z键瞬间显示内嵌JPG预览放大，0延迟。后台高优先级线程仅解码当前视口区域的RAW像素。解码完成后（目标<500ms）无缝替换为清晰RAW渲染。缓存在内存中，采用LRU策略，总上限2GB。解码失败则永久保留JPG预览并显示提示信息。

Z键补充细则：
1. 初始放大位置：默认以画面中心点为锚点放大100%。若上次在同一张照片上Z放大时曾平移过画面，则以记忆的上次位置为锚点（关闭软件后清空记忆）。
2. 视口外RAW解码策略：仅解码预览区当前可见的矩形区域，不解码整张RAW全尺寸。平移画面后按需增量解码新露出的区域，并合并进同一内存缓存纹理。
3. RAW解码失败持久化：若RAW解码失败，将该照片的 photo_id 写入数据库 decode_failed 标记位（持久化）。下次启动不再重试RAW解码，直接使用内嵌JPG预览，并在右侧信息面板中永久显示「此RAW解码失败，当前显示内嵌预览」灰色提示。用户可右键菜单选择「强制重试RAW解码」清除该标记后重试一次。
4. 仅预览模式标记（对应2.3节）：对于本软件格式不支持但能读到内嵌JPG的格式，Z放大仅用内嵌JPG放大，不尝试RAW解码，提示信息为「此格式暂不支持完整解码」。

7.5 直方图

常驻预览图右下角或侧边栏，实时显示当前RAW的曝光分布，辅助判断欠曝或过曝。

直方图细则：
1. 通道显示：默认叠加显示 R/G/B 三条独立曲线，加一条亮度（Luminance）混合曲线。右键直方图可切换仅R/仅G/仅B/仅L/全叠加五种模式。
2. 溢出警告：直方图左右两端0值或255值像素比例 > 3% 时，直方图左右两端边缘显示红色高亮点；预览区四角同时显示「高光溢出」或「暗部死黑」文字弱提示（可在设置中关闭）。
3. 数据来源：优先从RAW解码后的像素统计（已放大则用全图统计，不以视口区域采样）；若RAW不可用则用内嵌JPG统计。
4. 性能：直方图统计结果缓存，仅当切换照片或重新解码时重算。单张统计耗时目标 < 15ms。

7.6 自定义键位

支持在设置界面重映射核心快捷键，全局生效，一套键位适用于所有工作区。具体允许重映射与不允许重映射的键位清单、冲突处理规则详见 7.2.1。

7.7 排序

默认排序：按 EXIF 拍摄时间 capture_time 升序（从早到晚），与数据库索引 idx_photos_capture_time 对齐。
用户可在顶部栏排序下拉框中切换，所有排序均对当前过滤视图生效（不影响其他工作区，关闭软件后保留为默认排序）：
- 拍摄时间升序（默认）
- 拍摄时间降序（从新到旧）
- 原始文件名升序 A-Z
- 原始文件名降序 Z-A
- 文件大小升序（小→大）
- 文件大小降序（大→小）
- 导入时间升序
- 导入时间降序
- 状态分组（未处理→已阅→待删，各组内按拍摄时间）
次级排序规则：当主排序字段相同时，自动以「拍摄时间升序 → 文件名升序」作为次级排序，保证结果稳定可重现。
排序切换瞬切，< 30ms。缩略图条与预览区同步切换顺序。

7.8 过滤 / 搜索（仅显示符合条件的照片，不修改数据库状态）

入口：顶部栏搜索框 + 高级过滤按钮（漏斗图标）。

快速过滤（搜索框，回车触发）：
- 纯数字：匹配文件名主体中的数字串（例：输入 0342 匹配 DSC_0342.NEF）
- 含字母：模糊匹配文件名（大小写不敏感），例：输入 _G 匹配所有含_G的文件名
- @keyword：特殊前缀过滤（见下）

高级过滤（可叠加多选，所有条件之间是 AND 关系）：
- 状态：全部 / 未处理 / 待删 / 已阅跳过
- 相机型号：多选（从数据库已有相机型号中勾选）
- 镜头型号：多选（从数据库已有镜头型号中勾选）
- 光圈范围：最小 f/ - 最大 f/（滑块+输入框）
- 快门速度范围：最快 - 最慢（预设档位：1/1000、1/500、1/250、1/125、1/60、1/30、1/15、1s 等+手动输入）
- ISO 范围：最小 ISO - 最大 ISO（滑块+输入框，预设 100-3200 / 3200-25600 / 25600+ 快捷按钮）
- 焦距范围：最短 mm - 最长 mm（例：24-70mm）
- 拍摄日期范围：开始日期 - 结束日期（按 capture_time，支持快捷按钮：今日 / 昨日 / 最近7天 / 本月 / 上月）
- 文件格式：多选（NEF/CR2/JPG/PNG/HEIC 等）
- 是否丢失文件：是（仅显示current_path失效的）/ 否 / 全部
- RAW+JPG配对：仅显示配对组 / 仅显示单文件 / 全部

清除过滤：点击搜索框右侧 × 按钮一键清空所有过滤条件，恢复显示当前工作区全部照片。

7.9 批量操作

7.9.1 选择机制
缩略图条支持多选：
- 单击单张缩略图：单独选中一张（或取消已选），不影响预览区当前显示。
- Ctrl+单击：追加/移除单张到选区。
- Shift+单击：范围选，从当前锚点到点击位置的连续照片加入选区。
- Ctrl+A：全选当前过滤视图中的所有照片。
- Ctrl+Shift+A：清空选区。
- 选中的缩略图高亮：外边框 2px 实线，颜色 #ffb347（与当前选中张的3px边框颜色相同但更细，可区分「当前显示」和「批量选中」两种状态）。

7.9.2 批量操作命令（选中后可用）
- 批量待删（Ctrl+Q）：将所有选中照片标记为 status=1（待删），计数同步累加。
- 批量已阅跳过（Ctrl+E）：将所有选中照片标记为 status=2。
- 批量重置未处理（Ctrl+U）：将所有选中照片重置为 status=0。
- 批量删除丢失记录（仅当选中中含「文件丢失」灰标的照片时可用）：从数据库中移除这些文件丢失的记录（不碰磁盘）。
- 全部操作：
  - 不支持 Ctrl+Z 撤销批量操作（批量操作独立于单步撤销栈，避免栈溢出）。
  - 操作前在操作按钮上叠加显示「将对 N 张照片执行 X 操作」的二次确认浮层（可在设置中关闭此确认）。
  - 操作完成后状态栏显示「已对 N 张照片标记为 X」。


八、待删框

入口：界面右上角显示“待删（N张）”按钮。当 N=0 时按钮灰显，点击后弹出空状态提示「暂无待删照片」。

弹出方式：点击按钮弹出模态框，显示所有数据库内标记为待删的照片缩略图列表。

8.1 选择与批量操作

待删框内缩略图支持多选：
- Ctrl+单击：追加/移除单张。
- Shift+单击：范围选，按拍摄时间排序的连续区间。
- Ctrl+A：全选所有待删照片。
- Ctrl+Shift+A：取消全选。
- 选中的缩略图显示勾选角标（左上角 14x14px 复选框）。

8.2 恢复功能

按钮1：恢复选中（仅当有选中时可用，否则灰显）
- 行为：选中的照片从待删列表移除，数据库 status 重置为 0（未处理），文件原地保留。
按钮2：全部恢复（始终可用，N=0时灰显）
- 行为：清空当前所有待删照片，全部 status 重置为 0。
- 全部恢复后二次确认弹窗：「确定将 {N} 张待删照片全部恢复为未处理？」按钮「恢复全部」「取消」。

8.3 最终删除

按钮：删除所有（移到回收站）
- 触发后二次确认弹窗：警告内容为「即将永久删除 {N} 张照片（移入回收站，可在回收站恢复）。删除后数据库中的记录将彻底清除，无法在软件内撤销。是否继续？」
- 二次确认需额外安全校验：按钮文本不是简单的"确定"，而是"我已确认，删除 {N} 张"（需用户准确点击此按钮，避免误操作）。另一个按钮是"取消"。
- 执行过程：
  1. 逐张检查 current_path 是否仍然存在。
  2. 文件存在：调用 Windows API SHFileOperationW 将其移动到回收站（非彻底删除，保留用户在资源管理器中恢复的最后机会）。
  3. 文件不存在：跳过移文件操作，仅从数据库删除记录，在删除完成报告中单独列出「{M} 张文件已不存在，仅清理数据库记录」。
  4. 所有文件处理完毕后，开启事务一次性删除全部 status=1 的照片记录。
  5. 同步清理内存缓存与磁盘缩略图缓存中对应条目。
  6. 删除完成后在软件右上角 Toast 提示「已删除 {N} 张（移至回收站），清理 {M} 条残留记录」。

8.4 RAW+JPG 配对删除

见 6.1.3：整组删除，两个文件同时入回收站，两条记录同时删。删除完成报告中按组计数（显示 N 组，不显示 2N 个单文件）。


九、缓存策略

9.1 缩略图规格

基础规格（默认DPI=96，缩放=100%）：
- 列表/网格缩略图：256px 短边，JPEG 格式，质量 Q=80。
- 主视图预览图：1920px 长边，JPEG 格式，质量 Q=90。

高DPI适配（见十四、DPI 与多显示器）：
- 系统缩放比例 = s（s = 1.0 / 1.25 / 1.5 / 1.75 / 2.0 等）。
- 磁盘缓存同时生成基础版 + @2x 版（若 s ≥ 1.5 则生成 @2x；否则只生成基础版节省空间）。
- @2x 缩略图：512px 短边，Q=80；@2x 预览图：3840px 长边，Q=90。
- UI 渲染按当前显示器实际 DPR 自动选择使用 @1x 或 @2x 缓存。

9.2 存储位置

默认路径：%LOCALAPPDATA%/Kaka/cache/。
支持用户在设置中自定义路径。用户修改路径时，弹窗询问是否迁移现有缓存。选择迁移则后台复制所有缓存至新路径，完成后自动删除旧缓存。选择暂不迁移则新缓存写入新路径，旧缓存保留，软件提供“清理旧缓存”按钮供用户手动释放空间。

目录结构：
cache/
├── thumbs/          # 缩略图，文件名 = {thumb_hash}.jpg / {thumb_hash}@2x.jpg
├── previews/        # 预览图，文件名 = {thumb_hash}_preview.jpg / {thumb_hash}_preview@2x.jpg
└── cache_index.db   # 单独的 SQLite 小库，记录每张缓存的生成时间、大小、对应 photo_id，用于过期清理

9.3 生成时机

- 导入过程中后台异步生成，不阻塞UI。优先级：缩略图（先）→ 预览图（后）。
- 导入完成前已展示在缩略图条的照片若缓存未就绪，显示占位图（见UI加载态规范），缓存生成完后自动刷新显示。
- 导入时异常中断：下次启动或重新导入时，检测到数据库存在记录但 thumb_hash 对应的磁盘文件不存在，自动重新生成该缓存，不重新导入照片。

9.4 过期清理 + 总容量上限

双条件触发清理（任意一条满足即标记为可回收）：
- 时间条件：缓存文件生成时间距今 ≥ 30 天。
- 容量条件：cache 目录总大小 ≥ 设置中的上限（默认 20 GB，可在设置中 2GB-100GB 之间调节）。超过上限时按 LRU 淘汰，优先删除最久未被 last_access_time 访问的缓存，直到总占用降到上限的 85% 以下停止。

清理策略：懒加载 + 后台异步。启动时不清扫，边用边删，保证启动速度。当用户每浏览 50 张照片或每闲置 60 秒时，后台线程触发一次小清理（最多清理 100 个文件，不抢主线程IO）。设置中提供「立即清理全部过期缓存」按钮，点击后阻塞性清理并显示进度。

9.5 后台预解码

多线程优化。空闲时预解码当前照片前后各1张（仅解码适配屏幕尺寸的大预览图，非全尺寸），存入内存缓存，减少切换延迟。内存缓存总上限2GB。
LRU 策略，同一张照片若被频繁访问不会被淘汰；连续顺序浏览时（1→2→3→4…）预读窗口保持 ±1 张。

9.6 缓存重建

入口：设置 → 高级 →「重建全部缩略图与预览图」。
行为：
1. 遍历数据库中所有照片记录，逐个重新生成缩略图和预览图，覆盖旧缓存。
2. 过程显示进度条：当前处理文件名 + 进度（x/总），不阻塞UI，可后台执行，可随时取消（取消后已重建的部分保留）。
3. 重建完成后 Toast 提示「重建完成，共处理 N 张，失败 M 张（可查看日志）」。
4. 数据库损坏、thumb_hash 异常等情况，此功能相当于兜底修复入口。


十、数据库设计

10.1 Meta 元数据表（全局，id=1 单行）

CREATE TABLE IF NOT EXISTS meta (
    id              INTEGER PRIMARY KEY CHECK (id = 1),
    schema_version  INTEGER NOT NULL DEFAULT 1,  -- 数据库结构版本号，用于迁移
    app_version     TEXT,                         -- 上次写入此库的软件版本号，如 "0.1.0"
    created_at      TEXT DEFAULT (datetime('now')),
    last_migrated_at TEXT
);

10.2 照片主表 photos

字段列表：
id                    INTEGER PRIMARY KEY AUTOINCREMENT
original_filename     TEXT NOT NULL            -- 原始文件名，如DSC_0001.NEF
file_size             INTEGER NOT NULL         -- 文件字节数
capture_time          TEXT NOT NULL            -- EXIF拍摄时间，格式YYYY-MM-DD HH:MM:SS
current_path          TEXT NOT NULL            -- 当前硬盘上的绝对路径
folder_path           TEXT NOT NULL            -- 所在文件夹路径（不含文件名）

10.5 Schema 迁移机制

- 首次启动建库时，meta.schema_version 写入当前版本号（如 V1.0 = 1）。
- 软件每次启动连接 kaka.db 后，读取 meta.schema_version 与代码中内置的 TARGET_SCHEMA_VERSION 比较。
  - 相等：正常启动。
  - meta < TARGET：按迁移脚本顺序（1→2，2→3，…）依次执行，全部完成后写回 TARGET_SCHEMA_VERSION，过程全部在事务中执行，任一脚本失败则整体回滚，软件退出并提示「数据库迁移失败，已回滚，请联系开发者或手动恢复备份」。
  - meta > TARGET：用户用了新版软件再回到旧版，阻断启动并提示「此数据库由更高版本创建，请升级咔咔」。
- 每次迁移前自动备份 kaka.db 为 kaka.db.v{old_ver}.bak 到同一目录，保留最近3份备份，超出则删除最旧的。

10.6 数据库损坏检测与自动修复

- 启动时先执行 PRAGMA integrity_check; 若返回不是 "ok"，说明数据库损坏。
- 损坏处理流程：
  1. 弹窗告警：「检测到数据库损坏，尝试从最近备份恢复？」按钮：「自动修复并恢复」「手动选择备份文件」「放弃并新建空库（所有记录丢失）」。
  2. 自动修复：依次尝试 kaka.db.v{ver}.bak 3份备份，用最近一份可通过 integrity_check 的替换损坏文件。
  3. 全部失败或用户选择新建空库：将损坏文件重命名为 kaka.db.corrupted_{timestamp}，新建空 kaka.db 重新初始化。
- 日常写入全部开启 WAL 模式 + 每 1000 条写操作做一次 checkpoint，减少断电损坏概率。


十一、防丢失与自动保存

保存频率：每10秒自动保存当前工作区状态（浏览位置、所有Q/E标记、待删列表、排序方式、过滤条件、选区、缩放位置记忆）至SQLite。写入完成后清除 workspace_state.last_crash_marker = 0。
异常关闭检测：启动时若 last_crash_marker = 1（上次退出前未被清0），则判定为上次崩溃或强杀。

崩溃恢复流程：
1. 先展示导入续传检测（若有，见6.7.1），再展示工作区崩溃恢复。
2. 居中大弹窗：标题「检测到上次非正常关闭」。内容：「上次工作区：{current_folder_path}，已处理 {processed}/{total} 张。是否恢复上次的标记和浏览位置？」
3. 三个按钮：
   - 「恢复并继续」（默认按钮，#ffb347 高亮）：恢复 current_index、所有 status 标记、排序、过滤条件。
   - 「保留标记但从头浏览」：status 标记全部保留，但 current_index 重置为第1张，排序/过滤恢复。
   - 「放弃所有未保存的标记（重置为未处理）」：二次确认弹窗后，该工作区所有 status 重置为 0，current_index=0。
4. 恢复后在状态栏瞬时提示「工作区已恢复」。

正常退出标记：用户点击窗口×或 Alt+F4 或菜单退出时，在所有持久化写入完成后才销毁窗口，确保 last_crash_marker=0 持久化成功。

十二、导出筛选结果

筛选完成后提供四种导出方式，入口为顶部栏「导出」按钮（筛选终局检测触发后可用，其他时刻灰显）。

12.1 方式一：复制保留的照片到指定目录
- 弹窗选择目标文件夹，可选子目录组织方式（同导入6.1.2的三选项：保持原结构/按日期建子文件夹/平铺），默认保持原结构。
- 仅复制 status != 1（待删除外）的照片。RAW+JPG 配对则两张一起复制。
- 可选：是否同时写入同名 XMP 侧车文件包含旋转信息（rotation_override 不为0时写入 tiff:Orientation 标签），默认开启。
- 可选：是否复制同名 .xmp 原有 sidecar，默认开启（若存在）。
- 目标磁盘空间预检测：同6.1.4，不足则阻断。
- 进度条显示，支持取消。完成后报告：成功 N 张 / 失败 M 张 + 失败列表。
- 不触碰源文件、不修改数据库。

12.2 方式二：生成保留照片文件列表 .txt/.csv
- 格式一（.txt）：每行一个绝对路径，UTF-8 BOM，CRLF。
- 格式二（.csv）：三列：original_filename,current_path,status（0/2），首行表头，UTF-8 BOM。
- 用户选择保存位置和格式。

12.3 方式三：写XMP侧车标记状态（不复制文件，仅生成/修改 sidecar）
- 对所有保留照片（status != 1），在同目录生成或修改同名 .xmp，写入 xmp:Label 字段为「Kaka:Keep」，写入 crs:Rating 为 3 星（可在设置中自定义星级）。
- 对待删照片不写任何 sidecar（避免影响 LR）。
- 旋转信息：rotation_override != 0 时写入 tiff:Orientation。
- 原 sidecar 文件保留原有字段，仅追加/覆盖上述字段；不存在则新建标准 XMP。

12.4 方式四：发送到 Lightroom 经典版（见十三）

十三、Lightroom 联动（可选功能，V1.0若LR未安装则入口灰显）

检测方式：启动时读取注册表 HKLM\SOFTWARE\Adobe\Lightroom\CurrentVersion\InstallPath 或默认路径 C:\Program Files\Adobe\Adobe Lightroom Classic\Lightroom.exe 是否存在。若存在则开启联动入口。

13.1 一键导入保留照片到 LR 目录
- 入口：顶部栏「发送到 LR」按钮（同 12.4，筛选终局后可用）。
- 行为：
  1. 在系统临时目录生成一个 .lrtemplate 收藏夹描述文件，内容是所有保留照片的绝对路径列表（符合 LR 导入插件格式）。
  2. 调用命令行启动 LR 并传入该模板路径，LR 启动后自动将这些路径的照片「添加」（不复制文件）到当前目录。
  3. 若用户已配置了默认 LR 目录（可在咔咔设置中指定），则直接指定目录；否则让LR自己弹出目录选择。
  4. 同时按 12.3 写入 XMP sidecar，确保筛选后的保留/旋转信息在 LR 中可见。

13.2 失败处理
- LR 未检测到：入口灰显，悬停 tooltip 显示「未检测到 Lightroom 经典版」。
- LR 启动超时（15秒内无响应）：Toast 提示「Lightroom 启动超时，请手动导入临时收藏夹文件：{path}」，并提供「打开文件夹」按钮。
- 所有联动均不修改咔咔数据库，仅用于减少用户在 LR 中二次挑片的重复劳动。

十四、日志系统

日志文件位置：%APPDATA%/Kaka/logs/kaka_{yyyyMMdd}.log，每天一个新文件。
日志轮转：
- 单文件上限 50MB，超过则新建 kaka_{date}_1.log，_2…
- 总保留最近 14 天或 10 个文件（先到者为准），超出自动清理最旧文件。
日志级别（可在设置中切换，默认 INFO）：
- ERROR：导入失败、数据库写入失败、缓存生成失败、崩溃恢复失败、LR联动失败。
- WARN：EXIF编码兜底、空间不足预警、解码失败标记、唯一约束冲突跳过。
- INFO：导入开始/结束、筛选开始/结束、最终删除报告、工作区切换、自动保存触发。
- DEBUG：每张照片的缩略图生成耗时、切换延迟、缓存命中统计（仅开发构建默认开启，release构建默认关闭）。
日志格式（每行一条，JSON Lines，便于分析）：
  {"ts":"2026-08-24T10:00:00.123+08:00","level":"INFO","module":"import","msg":"import completed","success":327,"skipped":52,"failed":2}
设置中提供「在资源管理器中打开日志文件夹」按钮和「清空所有日志」按钮。
崩溃上报：若检测到 panic/未捕获异常，在关闭前尝试将 ERROR 级别堆栈写入 kaka_crash_{timestamp}.dmp（若操作系统允许），不联网上传，纯本地记录。

十五、DPI 与多显示器

全局策略：采用 Windows Per-Monitor V2 DPI Awareness。

15.1 主程序窗口缩放
- 启动时读取当前窗口所在显示器的 DPI 缩放比例 s（100%=96 DPI → s=1.0，150% → s=1.5，200% → s=2.0）。
- 所有 UI 尺寸（字体、图标、面板宽高、缩略图尺寸外框）按 s 等比缩放。
- 实际渲染的缩略图按9.1节选择 @1x 或 @2x 磁盘缓存，保证清晰。
- 字体：Segoe UI Variable 优先。若系统无此字体（Win10 旧版），降级顺序：Segoe UI → Microsoft YaHei UI → Arial。

15.2 跨显示器拖动
- 拖动窗口跨越不同 DPI 显示器边界时，实时重新计算新显示器的 s，对整个窗口重新布局和缩放。
- 切换过程中缩略图缓存自动从 @1x 切换到 @2x（若需要），过程中可能短暂模糊再变清晰（符合Windows原生行为）。
- 窗口最小/最大化时同样重新计算。

15.3 最小/最大窗口尺寸（硬约束，防止布局错乱）
- 最小宽度：1024 px，最小高度：640 px。用户尝试缩到更小时系统限制住。
- 全屏/最大化时按显示器物理分辨率自适应。

十六、首次启动引导（仅空白数据库首次启动时触发）

条件：meta.created_at 为当前启动新建 AND 当前数据库照片数=0。

引导界面为一个居中向导弹窗，分3步（可随时点「跳过引导」直接进入空状态）：
步骤1「欢迎」：标题「欢迎使用咔咔」。文字说明「只做导入+筛选，不做后期。快捷键Q待删/E跳过/Z放大。开始导入你的第一批照片吧！」按钮：下一步。
步骤2「基础设置」：
- 设置默认目标目录（复制模式默认路径，提供浏览选择）。
- 选择是否开启「检测存储卡自动弹出导入窗口」（默认开启）。
按钮：上一步 / 下一步。
步骤3「选择导入」：两个大卡片按钮（卡片1「从存储卡导入」卡片2「从硬盘文件夹添加」）。用户选一个则直接进入对应模式的导入窗口。也可以「稍后手动导入」返回空状态界面。
引导完成后：将用户设置写入数据库/配置文件。下次启动不再弹出。
空状态界面（UI规范对应）：若用户跳过引导或完成引导但暂未导入，显示大的占位+「点击「导入」开始」按钮，与引导卡片一致。

十七、设计原则总结

轻量化优先。不设精选键、不留删除历史、不主动弹窗检测丢失文件、不设复杂的项目文件概念。一切设计以「快速完成筛选」为核心目标，减少用户决策负担和系统资源消耗。
所有非核心功能（LR联动、导出XMP、高级过滤）在设置中均可关闭/隐藏，保证极简主义用户的界面纯净。
不内置自动更新机制；开源版本通过 GitHub Release渠道手动升级。

十八、打包部署
编译命令：cargo build --release
目标平台：Windows x86_64 优先（V1.0 不支持 aarch64 Windows / Linux / macOS，留待后续版本）。
Rust 编译配置建议 Cargo.toml：
  [profile.release]
  opt-level = 3
  lto = "fat"
  codegen-units = 1
  strip = "symbols"
  panic = "abort"
生成产物：target/release/kaka.exe（单个可执行文件）。
依赖情况：无任何外部依赖，无需安装 SQLite、无需 VC++ 运行库、无需 .NET Framework。Windows 10 21H2+ / Windows 11 原生环境双击即可运行。
数据库初始化：首次启动时自动创建 %APPDATA%/Kaka/ 目录及 kaka.db 数据库文件，自动建表及索引。用户无感知。
缓存目录默认路径：%LOCALAPPDATA%/Kaka/cache/，支持用户在设置中自定义。
卸载方式：删除 EXE 文件及 %APPDATA%/Kaka/ 目录即可完全清理。
分发方式：
- 标准版：提供 zip 压缩包，解压即用，无安装程序。
- 开源渠道（V1.0同步上线）：GitHub Release（附带 SHA256 校验文件 + 源码.zip）/ crates.io（若发布为cargo bin crate）。
- GitHub 仓库地址：默认官方仓库地址写死在软件中（设置→关于/导入导出 Tab 的「打开 GitHub 仓库」按钮使用）；若社区 fork 自建分发，可通过 %APPDATA%/Kaka/config.toml 中的 `github_repo` 字段覆盖（UI 中该字段暴露为「仓库地址」只读文本框）。
- 可选（V1.1+）：提供 winget / Microsoft Store / scoop 包。
数字签名：正式发布版 exe 附带 EV 代码签名证书，降低SmartScreen拦截率；纯社区自构建版本不强制签名。
升级说明：由于无自动更新，新版本发布时用户需手动从 GitHub 下载新版 exe 覆盖旧版，数据库与配置文件（均在 %APPDATA%/Kaka/）自动兼容旧版（通过 10.5 Schema 迁移机制保障）。
